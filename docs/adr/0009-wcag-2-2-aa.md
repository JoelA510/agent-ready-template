# 0009. WCAG 2.2 AA is the accessibility bar, with each new criterion's coverage stated

- **Status:** Accepted — target size and rendered contrast gated in a real browser by
  [0012](./0012-stories-in-a-real-browser.md)
- **Date:** 2026-09-24
- **Deciders:** template maintainers
- **Applies to:** the definition of done (feature-level and per-component), the PR template,
  CLAUDE.md, `docs/foundations/accessibility.mdx`, and every component in `src/components/ui/`

## Context

Every statement of the accessibility bar said WCAG 2.1 AA. WCAG 2.2 has been a W3C
Recommendation since October 2023. It keeps every 2.1 criterion except 4.1.1 Parsing, which it
made obsolete, and adds six at A and AA:

- 2.4.11 Focus Not Obscured (Minimum)
- 2.5.7 Dragging Movements
- 2.5.8 Target Size (Minimum)
- 3.2.6 Consistent Help
- 3.3.7 Redundant Entry
- 3.3.8 Accessible Authentication (Minimum)

The template's automated checks can see none of them:

- `check-contrast` measures color.
- `axe` in `npm run test` runs in jsdom, which has no layout, so its one 2.2 rule (`target-size`)
  can't measure anything there.
- The Storybook a11y panel runs in a real browser but is advisory (`test: 'todo'`).

Changing "2.1" to "2.2" alone would therefore raise the stated bar without checking anything
more.

## Decision

We will state WCAG 2.2 AA as the bar everywhere it appears, and pair it with an honest account of
how each new criterion is held. That account lives in the table in **Foundations →
Accessibility**:

- **Measured once, in a real browser:** target size. axe-core's `target-size` rule ran in Chromium
  over every built story, and again with each story's first overlay opened: 543 measurements,
  none failing. Controls that pass only through the spacing exception are listed, because the
  consuming app's layout decides for them.
- **Fixed in components where the library fell short:**
  - `SidebarMenuAction` and `SidebarGroupAction` go from 20px to 24px, because they overlap
    another target.
  - `Toaster` shows a close button by default, as an alternative to swiping.
  - `InputOTP` strips separators from a pasted code, so a formatted code isn't rejected.

  The last two are covered by behavioral tests that fail without the fix.
- **Named as gaps:**
  - `Resizable` has no single-pointer alternative to dragging.
  - Toasts render above modals and can cover a focused control.
- **Left to the app, and said so:** consistent help and redundant entry.

CLAUDE.md says that a green gate is not 2.2 conformance.

## Alternatives considered

### Alternative: stay on 2.1 until the new criteria can be gated

This would keep the stated bar and the enforced bar identical. It lost because 2.2 is the
current standard that procurement and legal requirements increasingly cite, and 2.4.11, 2.5.8,
and 3.3.8 describe failures real users hit. A bar that's honest about what's manual is better
than an outdated one.

### Alternative: gate target size in CI with a browser test runner

This would enforce 2.5.8 on every PR. It's deferred, not rejected: it needs a browser-based test
runner (Storybook's test runner or Vitest browser mode) in CI, a new dependency and CI job that
deserve their own change. Until then the measurement is a dated snapshot, and the doc says so.

## Consequences

- **Easier:** consumers get a bar that matches the current standard, and a list of exactly which
  parts they must check by hand.
- **Harder:** the per-component definition of done has three more items that only a person can
  verify, and the target-size numbers go stale when a control's size or spacing changes. The doc
  says to re-measure then.
- **Revisit** when a browser test runner lands (make target size a gate), or when WCAG 3 reaches
  Recommendation.
